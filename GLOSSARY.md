# Hotpot (`herdr-hotpot-agent`)

Canonical domain vocabulary for **herdr-hotpot-agent**, adapting the `paseo-room` orchestration philosophy (`Human / Supervisor / Lead / Peer`) natively to **Herdr** (`herdr-app` + `herdr-core` / `hc`).

## People and Seats

**Human** (or **Owner**):
The person who owns product goals, priorities, material cost, external effects, irreversible risk, and final authority over the project.
_Avoid_: user, admin, client

**Seat**:
A persistent role-bound agent configuration and runtime identity (`Supervisor`, `Lead`, or `Peer`) backed by an isolated `Role Home` under `~/.hotpot/` and executed inside a `herdr-core` (`hc`) terminal.
_Avoid_: bot, pane, subagent

**Supervisor**:
The governance and observation `Seat` dedicated 1:1 to a single `Project`. It stands outside the execution loop to route `Human` directives to `Lead` (`message_lead`), observe `Lead`–`Peer` workflows for anti-patterns or loss of momentum, receive `Attention Letters`, and replace a `Lead` past its context rotation mark after a reviewed handoff. It never edits code, directs `Peers`, or owns technical acceptance.
_Avoid_: manager, orchestrator, multi-project router

**Lead**:
The durable technical owner and binding arbiter of a single `Project`. It reads `WORKSPACE_PROTOCOL.md`, frames problems, decomposes and dispatches `Assignments` to `Peers`, runs `gate_run`, manually integrates committed `Candidates`, and owns technical acceptance (`assignment_accept`).
_Avoid_: foreman, root, senior coder

**Peer**:
An independent co-worker `Seat` executing a single bounded `Assignment` under one `Disposition` (`Engineer`, `Architect`, `Reviewer`, or `Scout`). It forms its own technical position from code and verification, challenges broken premises, and reports strictly through `ask` and `handoff` with zero orchestration tools.
_Avoid_: worker, subagent, slave

**Disposition**:
The operating stance assigned to a `Peer` in an `Assignment` brief: `Engineer` (writable within a declared scope), `Architect` (read-only design and trade-off analysis), `Reviewer` (read-only independent verification of a `Candidate`), or `Scout` (read-only codebase recon).
_Avoid_: persona, agent type

## Instructions and Capability Hygiene

**Hotpot Home (`~/.hotpot`)**:
The root directory in `$HOME` (overridable via `HOTPOT_HOME`) where `hotpot` stores generated `Role Homes`, `hotpot.json`, `AUTHENTICATION.md`, the `hotpot-project-onboarding` skill, and append-only runtime state (`~/.hotpot/runtime/v1/`).
_Avoid_: `~/.hotpot-room`, global agent home mutation

**Role Home**:
The role-isolated agent directory under `~/.hotpot/roles/<agent>/<role>/` generated by `hotpot setup --apply`. Each `Role Home` owns its mutable credentials and session history while closing all native multi-agent paths and projecting role-appropriate `skills`.
_Avoid_: clean-room sandbox, shared home

**Authentication Diagnostic**:
The non-blocking, secret-free, offline readiness state `hotpot verify` reports per Seat from credential-file presence and structural shape only: `configured structurally`, `login-required`, `legacy-shared-risk` (a symlinked/hardlinked credential shape), `diverged-file-preserve` (the live credential no longer matches the shape record `hotpot auth login` preserved beside it), or `native-keyring unverifiable`. Token values are never surfaced, no network call is made, and the states never affect the verify exit status — Capability Hygiene owns that.
_Avoid_: login check, credential scanner

**Capability Hygiene**:
The configuration boundary that withholds orchestration surfaces (`hotpot*` and `paseo*` skills, `plugins`, `hooks`, `commands`, `prompts`, and orchestration MCP tools) from `Peer` and closes native subagent spawning across all `Seats`, without pretending to be an OS-level shell sandbox.
_Avoid_: PreToolUse sandbox, regex firewall

**Skill Projection**:
The copy of an operator skill tree a `hotpot setup` run places under Hotpot Home. The Lead Aggregate (`skill-projections/<agent>/lead/`, wired into each Lead's `skills` symlink) carries every non-colliding, non-orchestration operator skill in full plus the built-in `hotpot-project-onboarding` skill; the Peer projection (`roles/<agent>/peer/skills/`) additionally withholds executable resources and any skill referencing the Workspace Protocol. Collisions (one skill name from several operator roots) are excluded everywhere and reported in the setup plan.
_Avoid_: skills symlink farm, vendor skill sync

**Workspace Protocol (`WORKSPACE_PROTOCOL.md`)**:
An optional file at a repository's root defining repository-specific workflow tactics (topology, model routing, proof gates, review rules). Read exclusively by `Lead` and drafted proposal-first via the `hotpot-project-onboarding` skill under explicit `Human` instruction; `Peer` is never told the file exists.
_Avoid_: global workflow doc, `AGENTS.md` orchestration dump

## Work, Evidence, and Attention

**Project**:
One Git repository mapped to a Herdr Space and owned by at most one active `Lead` and one dedicated `Supervisor`.
_Avoid_: folder, portfolio

**Assignment**:
A bounded unit of delegated work (`asg_<id>`) created and dispatched by `Lead` to a `Peer`, stating the desired outcome, `Disposition`, optional `Write Scope`, and `Gate` command without pre-solving the implementation.
_Avoid_: wave task, 4-part contract template

**Writer Lease**:
The exclusive reservation required before an `Engineer` `Peer` may write: either a single writer in the main checkout (locking writes from all other seats until `handoff`) or up to three concurrent isolated worktree writers whose `Write Scope` and `serialOnly` paths do not overlap.
_Avoid_: uncoordinated parallel edits

**Write Scope**:
The repository-relative path or glob set declared on a writable `Assignment` to detect cross-writer collisions (`scope_overlap`, `serial_path`) and post-handoff out-of-scope edits (`scope.exceeded`).
_Avoid_: chroot jail, hard write fence

**Candidate**:
An immutable Git commit (`baseCommit..HEAD`) produced by an `Engineer` `Peer` in a clean working tree and handed back via `handoff` for `Gate` verification, optional independent review, and manual integration by `Lead`.
_Avoid_: uncommitted diff, auto-merged branch

**Gate**:
The repository verification command named in an `Assignment` that the `Peer` must run before `handoff` and that `Lead` may independently re-execute via `gate_run` against a `Candidate`.
_Avoid_: lint hook, self-acceptance

**Challenge Signal**:
A structured premise pushback (`REOPEN_REQUEST`, `DEPENDENCY_REQUEST`, or `BLOCKED`) raised by a `Peer` via `ask` or `handoff` when an `Assignment`'s assumptions contradict repository reality.
_Avoid_: silent workaround, scope creep

**Attention Letter**:
A batched, evidence-backed notification (`[hotpot attention att_<id>]`) delivered to the `Project`'s `Supervisor` when the runtime detects a stalled permission, an unread `Peer` handback, repeated failures, `NEEDS-HUMAN:` or `INCIDENT:` markers, or `Lead` context crossing its rotation mark.
_Avoid_: polling loop, raw log stream
